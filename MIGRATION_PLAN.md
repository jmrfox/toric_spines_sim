**Follow-up (2026-11-08):** Arbor is now off `main` entirely, with no dependency group and no evidence folder. Branches:
- `arbor-legacy`: the last Arbor-based package (`f02db59`).
- `arbor-evidence`: the evidence scripts, frozen Arbor model and golden-baseline generator, next to the new package.

`main` keeps the golden baselines as fixed test data.

**Departures from the plan:**
- **Default solver is `"auto"`, not `"jaxley"`.** The speed decision point came out clearly. After the Woodbury update the reference solver takes 2.9 s per simulated second on TS3, against 20 s for warm Jaxley, so passive runs use the reference solver and HH runs use Jaxley. The two agree to about 1e-5 mV.
- **Batching gives no speedup for looped cells.** JAX's sparse solver has no `vmap` rule, so `run_batch` uses `lax.map` (sequential, compiled once). Tree cells still vectorize.
- **Pre-existing breakage found, not fixed:** `simulations/ts1/hypergrid` (gitignored) expects grid points and an `n_axons` parameter that the ICx banks have not had since the September split.


**Why.** Loop closure is mandatory, and Arbor cannot do it. Arbor cells are trees, and a gap junction uses the peer voltage from the start of the step, which adds a fake capacitance of `g·dt` at each end (`scripts/diagnostics/gj_fake_capacitance.py`). Jaxley closes loops exactly when the extra edges go into its sparse solve (cabaret plan 007). The prototype matches the reference solver to 1e-5 mV (`scripts/diagnostics/jaxley_vs_reference.py`).

**End state.**
- Jaxley (`>=0.14,<0.15`) is the only production simulator.
- The loop-capable reference solver (`simulation/reference.py`) stays as the independent check.
- Arbor and the NMODL catalogue are removed from the package. The Arbor evidence scripts are kept in an optional group, because the MASCAF revision cites them.

## Phase 2: complete the Jaxley backend (3–5 days)

Starting point: `simulation/jaxley_backend.py` (AMPA, NMDA, passive, loops).

1. **Synapses.** All five registry models are linear-kinetic in time, so precompute each one's conductance from its spike times and clamp it onto the compartment:
   - AMPA and GABA_A: single exponential.
   - NMDA and GABA_B: dual exponential, peak-normalized.
   - effexc: AMPA plus NMDA, with `nmda_ratio`.
   - Only the NMDA Mg block depends on voltage; it stays inside the channel.
2. **HH.** Subclass `jaxley.channels.HH` to evaluate gates at `v + v_rest`, because the cell runs in deviations from rest. Paint it by `hh_tags` / `hh_scale`. Lumped-sink HH needs densities based on the real area: decide this here or keep the current warning.
3. **Compile once.**
   - Build and jit one function per (morphology, discretization, synapse layout).
   - Pass parameters and event-derived conductances as arguments, so changing inputs doesn't recompile. Today each run pays about 10 s of setup.
4. **Batching.**
   - Add `run_batch(list_of_inputs)` using `jax.vmap` over conductance series and parameters, for axon studies, neurosignature trials and hypergrid sweeps.
   - Measure throughput, and GPU float64 if a CUDA machine is available.
5. **Guards.**
   - Turn on float64.
   - Refuse `jaxley.dhs` for looped cells.
   - Pin `jaxley<0.15` and test that `_comp_edges` still has the expected columns, so a Jaxley upgrade fails loudly.
   - Upstream the cabaret issue asking for public loop support.

**Acceptance:**
- Jaxley vs reference: max difference under 1e-3 mV (AMPA, GABA) and under 0.5% of peak (NMDA, linearization) on all nine spines, at two dt values.
- Jaxley vs the phase-0 HH golden traces: under 1% of peak on TS48 and TS76.
- A batch of 32 TS3 one-second runs is timed and the number recorded.

## Speed: decision point after phase 2

Measured on CPU for TS3 at dx = 0.25 µm, one simulated second:

| Solver | Time | Loops |
|---|---|---|
| Arbor | 0.4 s | not closed |
| Reference (scipy) | 18 s | closed |
| Jaxley | ~10 s setup + ~11 s per simulated second | closed |

If phase 2's compile-once and batching don't bring sweeps into an acceptable range, there are two cheap fallbacks:

1. **Speed up the reference solver for passive studies.** Factor the matrix once and handle the synapse conductance changes with a small low-rank update (Woodbury), since only the synapse compartments change. This is probably 10–50× faster, with no new dependency.
2. **Run sweeps on a GPU machine** with Jaxley in float64.

## Order and size

Phases 0 → 1 → 2 → 3 must go in order. Phase 4 can start after phase 1. Phase 5 comes last.

Rough total: **2–3 weeks**, plus re-running studies.

Each phase ends with the test suite passing and its own commit, on a branch off `review-fixes` (or off `main` once those fixes are merged).

## Risks

| Risk | Mitigation |
|---|---|
| Jaxley changes `_comp_edges` (private API) | Pin `<0.15`; schema test; upstream issue for public loop support |
| Speed of sweeps | Compile once, batch, GPU; fast reference fallback |
| HH port mismatch | Phase-0 Arbor golden traces on loop-free spines |
| float64 cost on GPU | Measure in phase 2 before planning sweeps around a GPU |
| Downstream code relying on Arbor objects in `SimulationResults` | Phase 3 keeps the trace and probe layout; only `results.py`/`kmatrix.py` read those fields |
